# Shared experiment authoring

Shared science uses the same `experiment.py --config REQUEST` entry and `jscc-experiment-v1` envelope with `workflow: shared`. Select one operation per call; [operation fields and effect boundaries](operations-workflow.md) define asset checks, prepare/train/resume/evaluate/collect and preview/submit. `shared-codec-recipe-v1` remains an internal resolved/saved meaning and historical reader input, not a second public CLI.

The current shared HellaSwag reference/example files compose dedicated `base.yaml`. Science owns ordered topology-valid locations, positive updates_per_location, unique widths/reconstruction_percentages, supported effective overrides, encoder/decoder/functional objective weights, save fractions, observations and evaluation. Resolution uses a local pinned backbone config.json to verify actual topology without downloading or loading weights.

Supported envelope: native batch16/accumulation1, direct-affine/native arithmetic, canonical codec ownership, AWGN or identity, reconstruction then additive reconstruction+KL, with one optimizer/LR reset. HellaSwag source 2048/target 512 and existing prompt/family/scorer identities remain unchanged. Unsupported batching/design/channel/phase choices reject. Ordinary stopping/selection keys such as patience/eval_every/monitor/validation_snrs are not shared controls and cannot be explicitly overridden.

For N locations and per-location Q updates, the optimizer horizon N×Q and base presentations Q×16 are derived. All sites see the same complete indexed view. Requested data amount and actual selected rows are recorded separately; data seed, membership and paired noise retain exact identities. Reconstruction percentages require integral phase quotas. Save and observation states come from the existing plan algebra, not a second arbitrary phase engine.

Acquire locally attests already complete pinned model bytes. Register chooses checksum-bound model/cache/observation/terminal references or one retained prepared receipt. Automatic preparation selects exact acquired registrations and reuses cached inputs/initializers. Explicit assets preparation retains its exact model_config/cache/initializer/template/source binding. Preparation never constructs the backbone or trains. Standalone receipts and bound roots are separate fresh destinations.

Training consumes the exact prepared root or a supplied checksum-bound prepared reference; it does not acquire/register/choose latest assets. Root/case/attempt/source/runtime/effective science stay bound. Distinct cases own independent training reservations. Resume supplies one exact case and durable checkpoint role/step/parent/size/hash, restoring next view/site/phase/reset/optimizer/LR/scaler/RNG/exposure. Production execution still requires clean source; a refactor's dirty checkout is not a compatible scientific release.

Terminal evaluation defaults to this case's own frozen terminal. Development observations require their exact configured checkpoint role and step; supplemental scope uses predeclared conditions. Task/input/scorer/site/noise/count restoration and output ownership remain verified. Per-case and aggregate receipts expose completed/failed/missing/pending denominators, with incomplete results ineligible for the final gate. Collection is separate.

Shared COCO uses acquired image inventories, deterministic indexed caption choices, demo/reference membership, processor assets and scorer identities. The multimodal teacher/student paths retain clean image-aware encoder/decoder targets and receiver memory. COCO terminal and observation panels generate captions and score CIDEr against the bound complete reference corpus; image shards are not averaged. Local cached inputs are required, and a check example supplies no training or launch authority.

Single-case parallel evaluation assigns whole site/condition panels to isolated processes, loads one model per worker and uses one parent aggregate writer. Its exact `evaluation.parallel` fields, distinct device/output ownership, completed/failed/missing/pending/interrupted states and fresh linked retry semantics are documented in [operations](operations-workflow.md#parallel-panels-of-one-shared-case). A complete panel set cannot satisfy pending required training observations. Full-weight fit, speed, quality, recipes/budgets and launch authority are not inferred from CPU/mock refactor checks. Prompt-length research and new scientific recipe/budget selection remain deferred owner decisions; COCO correctness and parallel failure/continuation mechanics are required implementation behavior.

Saved compatibility readers live in checkpoint_readers.py and preserve established schema/protocol/noise/parameter/source meanings. Old queued bundles and frozen experiment artifacts use their original source; reorganizing current authoring does not rewrite them. Historical campaign fronts do not become alternative current executors merely because their evidence remains readable.
